Hermes on NemoClaw — IT-Admin Deployment Guide

Who this is for: enterprise IT admins rolling out the deskside Hermes agent stack (NemoClaw + Hermes + local vLLM) on Dell fleets.

Developer quick-start: Developer Deploy Guide.

This guide covers a fleet install of the Hermes on NemoClaw solution on Dell workstations. It assumes:

  • Dell Pro Precision with GB10/GB300 or Dell Pro Precision 9 tower (T2/T4/T6) hardware with NVIDIA GPUs (S / M / L tiers).
  • Ubuntu 24.04 LTS or newer on Dell Pro Precision 9 towers and Dell Pro Precision with GB300; GB10 systems ship with DGX OS.
  • A control node with administrative access to every target host.
  • One IdP-integrated account per developer / operator using the agent.

Overview

The solution deploys in planes that can be installed and upgraded independently:

Plane Contents Install path
Plane 0 — Prerequisites Docker CE + NVIDIA Container Toolkit + secrets + disk for weights Ubuntu package install
Plane 1 — Serving vLLM + Nemotron + Prometheus + Grafana Per-platform recipe from recipes/ (Docker Compose)
Plane 2 — Agent NemoClaw → OpenShell → Hermes sandbox + policy NVIDIA installer + nemohermes onboard

The same Plane 1 endpoint is reusable across other solutions in this repository (Agentic Coding, video search, etc.) — you do not need one vLLM instance per solution on the same workstation.

Plane 0 — Prerequisites

Every target host must have:

  • Docker CE ≥ 24 and NVIDIA Container Toolkit — verify with: bash docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu24.04 nvidia-smi
  • Hugging Face token (HF_TOKEN) with access to the Nemotron 3.5 Lightning NVFP4 model, or the weights already staged in ~/.cache/huggingface.
  • ~30 GB free in the Hugging Face cache path.
  • Outbound network access to huggingface.co, nvidia.com, github.com from Plane 2 hosts for the initial NemoClaw installer run.

Optional but recommended:

  • Prometheus + Grafana already stood up on the box (Plane 1 recipes bring their own — you can either reuse or run co-tenant).
  • A reverse proxy (nginx / Caddy / Traefik) in front of vLLM if agents will be reached from anywhere other than localhost.

Plane 1 — Serving

Single host — run the recipe

Pick the recipe matching the host's platform and run it directly:

Commands in this guide run from the repository root (git clone this repo and cd into it).

recipes/<platform>/vllm/docker-nemotron-3.5-lightning-nvfp4.sh --port 8000
curl -sf http://localhost:8000/health && echo VLLM_OK

Recipes automatically apply the validated flag set (MoE backend, KV-cache dtype, tool-call parser) — see Deployment Recipes.

Platform Recipe directory
Dell Pro Precision with GB10 recipes/gb10/vllm/
Dell Pro Precision 9 T2 / T4 / T6 (1× / 2× / 5× RTX PRO 6000) recipes/precision/vllm/
Dell Pro Precision with GB300 recipes/gb300/vllm/

Multi-host fleet

Use Canonical Landscape script execution (Fleet Deploy via Landscape) or your own automation; every recipe blocks until ready and exits non-zero on failure. Map hosts to per-tier recipes (recipe catalog); HF_TOKEN is needed unless weights are pre-cached.

Verify Plane 1

Once vLLM is up, the following should all succeed:

curl -sf http://localhost:8000/health           # 200 OK
curl -s  http://localhost:8000/v1/models        # lists nemotron-lightning
curl -sfI http://localhost:3000/login | head -1 # Grafana 200
curl -sf  http://localhost:9090/-/healthy       # Prometheus OK

Plane 2 — Agent

NemoClaw and Hermes are installed via NVIDIA's official installer — this guide only covers the wire-up to Plane 1 and the operator-tier settings. (For a fleet, scripts/landscape/deploy-solution.sh runs the install non-interactively; inline path below.)

curl -fsSL https://www.nvidia.com/nemoclaw.sh | bash

# Onboard the runtime. Choose Hermes / nemohermes when the wizard prompts.
nemoclaw onboard

# Wire agent inference to the Plane 1 endpoint on this host:
openshell provider create \
  --name vllm-local \
  --type openai \
  --credential OPENAI_API_KEY=local \
  --config base_url=http://host.docker.internal:8000/v1

openshell inference set --provider vllm-local --model nvidia/nemotron-3.5-lightning
openshell status

Agent policy

Every Hermes sandbox runs under a NemoClaw policy that governs filesystem access, network egress, and subprocess boundaries. Ship the standard tier policy for enterprise deployments — never leave permissive in production.

Three policy tiers ship with NemoClaw (standard, strict, permissive). Save your tier as a policy file and apply it at sandbox creation:

nemohermes create <sandbox-name> --policy solutions/hermes-on-nemoclaw/policy/standard.sample.yaml

Filesystem landlock and network policy behave differently:

  • Filesystem landlock must be set at sandbox create time. openshell policy set cannot retrofit filesystem constraints on a running sandbox.
  • Network policy can be applied live via openshell policy set on a running sandbox.

Before handing a host to a developer, confirm:

Monitoring

  • vLLM exposes /metrics (Prometheus format). Each recipe starts the shared tokenomics Prometheus + Grafana (monitoring/README.md) covering tokens, cost vs cloud, utilisation, TTFT / ITL, KV-cache and queue depth.
  • NemoClaw emits agent-level telemetry (task success rate, agent turns, tool-call counts). See NVIDIA NemoClaw documentation for the metric names.
  • GPU telemetry via NVIDIA DCGM exporter (recommended add-on).

Lifecycle

Operation How
Update the LLM Change the recipe's model tag, re-run the recipe.
Update the agent Re-run the NemoClaw installer.
Rotate HF_TOKEN Update the secret in your secret store; restart the vLLM container.
Rollback Recipes are idempotent; docker stop the current container and re-run with the previous image tag.
Uninstall docker rm -f the vLLM container + Plane 2 uninstall per NVIDIA installer.

Common issues

Symptom Fix
vLLM never becomes healthy Weights download on first boot (~20 GB). Watch docker logs <container> for Application startup complete. — usually 1–3 min on cached weights, 10–20 min on cold pull.
nemohermes exec denied by network policy Add the local Plane 1 host to the sandbox network policy; prefer host.docker.internal:8000 over 127.0.0.1:8000.
Rootless Docker + --ulimit memlock=-1 fails Set NEMOTRON_LIGHTNING_ROOTLESS=1 before running the recipe (drops the memlock ulimit).
Hermes oneshot exceeds context on first try Add model.max_tokens: 4096 to the sandbox Hermes config.

Multi-user identity

Hermes inherits the host's identity by default. For multi-user M / L deployments:

  • Front the vLLM endpoint with a reverse proxy that terminates AD / LDAP / OIDC and injects the identity into the request.
  • Use per-user Hermes sandboxes so tool-execution policies and long-running state are scoped per operator.

Identity integration is intentionally out of scope for the base install — the solution is agent-first; the identity integration is a deployment decision per site.
